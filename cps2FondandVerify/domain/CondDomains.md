# Conditional FOND 论域说明 (CondDomains)

本文档记录 `cps2FondandVerify/domain/` 下四个条件化 FOND (Conditional FOND) 论域——**TreeChop、NestedVar、Snow、DeliveryFuel**——的高层语义、低层 PDDL 建模、实例及它们与 FOND 抽象（`autogenerated/` 中无对象、仅保留导出谓词的 non-deterministic PDDL）之间的对应关系。每个论域的核心特征是：高层 Golog 程序使用**带参动作（parameterized actions）**，而抽象后的 FOND 域将所有对象量化掉，仅通过一阶导出谓词（derived predicates）刻画状态的"抽象特征"（abstract features）。

---

## 1. TreeChop —— 砍树

### 1.1 高层语义

一棵树由**树干（Trunk）**和若干**树枝（Branch）**组成。机器人需要用单手依次将树枝砍下、丢弃到地面；当所有树枝都被砍掉后，才能将树干推倒（fellTree）。

- **资源约束**：只有一只手（`arm_empty`），同一时刻只能持有一根树枝（`holding`）。
- **进度判据**：导出谓词 `allBranchesChopped` 为真当且仅当 ∀b (chopped(b) ∨ b=Trunk)，即所有非 Trunk 对象都已被砍下。
- **终态**：`treeDown` 为真。

### 1.2 低层 PDDL 动作（`domain/TreeChop/low_TreeChop_d.pddl`）

| 动作 | 参数 | 前提 | 效果 |
|------|------|------|------|
| `chopBranch` | `?b - BranchType` | `onTree(?b) ∧ clear(?b) ∧ arm_empty` | `holding(?b), ¬arm_empty` |
| `dropBranch` | `?b - BranchType` | `holding(?b)` | `chopped(?b), arm_empty, ¬holding(?b)` |
| `fellTree` | (无) | `allBranchesChopped ∧ arm_empty ∧ ¬treeDown` | `treeDown` |

### 1.3 导出谓词

| 谓词 | 定义 |
|------|------|
| `allBranchesChopped` | `∀b (chopped(b) ∨ b=Trunk)` |
| `H` | `∃b holding(b)` |
| `vGoal` | `treeDown` |

### 1.4 约束条件（`constrainsConfig/treechop_constrain.txt`）

```
f0: ¬H → arm_empty        （手里没东西等价于手臂空闲）
f1: arm_empty → ¬H
f2: ¬treeDown → ∃b (onTree(b) ∧ clear(b) ∧ b≠Trunk)  （树未倒则至少还有树枝可砍）
f3: allBranchesChopped → ¬∃b (onTree(b) ∧ b≠Trunk)
```

### 1.5 实例

| 实例 | 对象 | 描述 |
|------|------|------|
| `low_TreeChop_p1.pddl` | 仅 Trunk | 没有树枝，`allBranchesChopped` 在 forall 空集上直接为真，直接执行 `fellTree` 一步即可 |
| `low_TreeChop_p2.pddl` | Trunk, b1, b2 | 两根树枝均 `onTree` 且 `clear`。依次 chopBranch→dropBranch→chopBranch→dropBranch→fellTree |

### 1.6 FOND 抽象

FOND 域中所有 BranchType 对象被量化消除，仅保留三个布尔抽象特征：`vStart`、`vGoal`、`allBranchesChopped`、`H`。

- 虚拟源动作非确定地分支到 `(¬allBranchesChopped, ¬H)` 或 `(allBranchesChopped, ¬H)`，对应实例 p2 与 p1 的初始抽象。
- `dropBranch` 的非确定性：丢掉一根树枝后，`allBranchesChopped` 可能仍为假（还有树枝）或变为真（最后一根）。

**抽象状态转移图**：

```
vStart ──(virtual_source)──→ [¬ABC, ¬H] ──chopBranch──→ [¬ABC, H] ──dropBranch──→ [¬ABC, ¬H]  (还有树枝)
                                                              └──dropBranch──→ [ABC, ¬H]    (最后一根)
                                                                                   │
                                                                              fellTree
                                                                                   ↓
                                                                               [vGoal]
```

## 2. NestedVar —— 嵌套变量递减

### 2.1 高层语义

模拟两个变量 `X1` 和 `X2` 之间的嵌套递减过程：
- X1 初始存有若干物品（`ItemType`），X2 始态为空（`x2empty`）。
- 只有当 X2 为空时，才可将 X1 的一个物品移入 X2（`decX1`）。
- 然后可将 X2 中的物品删除（`decX2`），使 X2 重新变空。
- 重复直到 X1 和 X2 均为空。

此结构可视为"嵌套循环"的抽象模型：外层每轮从 X1 取一个物品，内层处理 X2 中的那一项。

### 2.2 低层 PDDL 动作（`domain/NestedVar/low_NestedVar_d.pddl`）

| 动作 | 参数 | 前提 | 效果 |
|------|------|------|------|
| `decX1` | `?i - ItemType` | `inX1(?i) ∧ x2empty` | `inX2(?i), ¬inX1(?i), ¬x2empty` |
| `decX2` | `?i - ItemType` | `inX2(?i)` | `¬inX2(?i), x2empty` |

### 2.3 导出谓词

| 谓词 | 定义 |
|------|------|
| `h_x1empty` | `¬∃i inX1(i)` |
| `h_hasX2` | `∃i inX2(i)` |
| `vGoal` | `h_x1empty ∧ ¬h_hasX2`（两者皆空） |

### 2.4 约束条件（`constrainsConfig/nestedvar_constrain.txt`）

```
f0: ¬h_hasX2 → x2empty
f1: x2empty → ¬h_hasX2
f2: ∃i inX1(i) → ¬∀i ¬inX1(i)   （X1 非空则确实有物品）
```

### 2.5 实例

| 实例 | 对象 | 初始状态 |
|------|------|----------|
| `low_NestedVar_p1.pddl` | a1, a2 | `inX1(a1), inX1(a2), x2empty` |

执行序列：decX1(a1)→decX2(a1)→decX1(a2)→decX2(a2)，共 4 步。

### 2.6 FOND 抽象

FOND 域仅保留 `h_x1empty` 和 `h_hasX2` 两个抽象特征。

**抽象状态转移图**：

```
vStart ──(virtual_source)──→ [¬h_x1empty, ¬h_hasX2] ──decX1──→ [¬h_x1empty, h_hasX2]  ──decX2──→ [¬h_x1empty, ¬h_hasX2]  (循环，X1 还有物品)
                                                      └──decX1──→ [h_x1empty, h_hasX2]    ──decX2──→ [h_x1empty, ¬h_hasX2] = vGoal  (最后一轮)
```

`decX1` 的非确定性体现在：从 X1 取走一个物品后，X1 可能仍非空（还有物品）或变空（取走最后一件）。

## 3. Snow —— 扫雪

### 3.1 高层语义

机器人需要在**干雪区（dry）**和**湿雪区（wet）**两个位置之间移动，分别清除对应类型的雪堆：
- 在 dry 位置可以执行 `shovelDry` 清除干雪堆。
- 在 wet 位置可以执行 `shovelWet` 清除湿雪堆。
- 通过 `moveDry` / `moveWet` 在两个位置间切换。
- 起始和结束都必须在 dry 位置，且所有雪堆必须被清除完毕。

### 3.2 低层 PDDL 动作（`domain/Snow/low_Snow_d.pddl`）

| 动作 | 参数 | 前提 | 效果 |
|------|------|------|------|
| `shovelDry` | `?l - LocationType` | `atDry ∧ drySnow(?l) ∧ ¬dryCleared(?l)` | `dryCleared(?l), ¬drySnow(?l)` |
| `shovelWet` | `?l - LocationType` | `atWet ∧ wetSnow(?l) ∧ ¬wetCleared(?l)` | `wetCleared(?l), ¬wetSnow(?l)` |
| `moveDry` | (无) | `atWet` | `atDry, ¬atWet` |
| `moveWet` | (无) | `atDry` | `atWet, ¬atDry` |

### 3.3 导出谓词

| 谓词 | 定义 |
|------|------|
| `allDryCleared` | `∀l dryCleared(l)` |
| `allWetCleared` | `∀l wetCleared(l)` |
| `allCleared` | `allDryCleared ∧ allWetCleared` |

### 3.4 约束条件（`constrainsConfig/snow_constrain.txt`）

```
f0: atDry → ¬atWet
f1: atWet → ¬atDry
f2: ∃l drySnow(l) → ¬allDryCleared
f3: ∃l wetSnow(l) → ¬allWetCleared
```

### 3.5 实例

| 实例 | 对象 | 描述 |
|------|------|------|
| `low_Snow_p1.pddl` | d1,d2,d3 (干雪), w1,w2,w3 (湿雪) | 3 处干雪 + 3 处湿雪，起始 atDry。需交替移动和铲雪 |

### 3.6 FOND 抽象

FOND 域中 `atDry`/`atWet` 被抽象掉（因为它们是运行时状态而非最终关心的特征），仅保留 `allDryCleared`、`allWetCleared`、`allCleared`。值得注意的是，由于 FOND 抽象不跟踪位置，铲雪动作的结果变为非确定——可能成功清除也可能未完成（对应低层中位置不对无法执行的情况）。

## 4. DeliveryFuel —— 快递送油（燃料约束递送）

### 4.1 高层语义

一辆卡车在**仓库（Depot）**和**客户（Customer）**之间运输包裹：
- 在仓库装货（`loadPkg`）。
- 开车到客户处（`moveToCustomer`）。
- 在客户处卸货（`unloadPkg`）。
- 开车回仓库（`moveToDepot`）。
- 在仓库加油（`refuel`）。

**核心约束**：每次移动都消耗一单位燃料（`fuelOK → fuelLow`），必须回到仓库才能加油（`refuel`）。这迫使"一次只能送一个包裹"的行为模式：装货→去客户→卸货→回仓库→加油，循环直到全部包裹送达。

### 4.2 低层 PDDL 动作（`domain/DeliveryFuel/low_DeliveryFuel_d.pddl`）

| 动作 | 参数 | 前提 | 效果 |
|------|------|------|------|
| `loadPkg` | `?p - PackageType` | `atDepot ∧ atDepotPkg(?p) ∧ fuelOK` | `inTruck(?p), ¬atDepotPkg(?p)` |
| `unloadPkg` | `?p - PackageType` | `atCustomer ∧ inTruck(?p)` | `delivered(?p), ¬inTruck(?p)` |
| `moveToCustomer` | (无) | `atDepot ∧ fuelOK` | `atCustomer, ¬atDepot, ¬fuelOK, fuelLow` |
| `moveToDepot` | (无) | `atCustomer ∧ fuelOK` | `atDepot, ¬atCustomer, ¬fuelOK, fuelLow` |
| `refuel` | (无) | `atDepot ∧ fuelLow` | `fuelOK, ¬fuelLow` |

### 4.3 导出谓词

| 谓词 | 定义 |
|------|------|
| `vGoal` | `atDepot ∧ allDelivered` |
| `allDelivered` | `∀p delivered(p)` |
| `h_carrying` | `∃p inTruck(p)` |

### 4.4 约束条件（`constrainsConfig/deliveryfuel_constrain.txt`）

```
f0: atDepot → ¬atCustomer
f1: atCustomer → ¬atDepot
f2: fuelOK → ¬fuelLow
f3: fuelLow → ¬fuelOK
f4: ∃p inTruck(p) → ¬allDelivered
```

### 4.5 实例

| 实例 | 包裹数 | 描述 |
|------|--------|------|
| `low_DeliveryFuel_p1.pddl` | 1 (p1) | 1 个包裹，最短路径：load→moveToCustomer→unload→moveToDepot→refuel |
| `low_DeliveryFuel_p2.pddl` | 2 (p1, p2) | 循环两次 |
| `low_DeliveryFuel_p3.pddl` | 3 (p1, p2, p3) | 循环三次 |

### 4.6 FOND 抽象

FOND 域仅保留 `allDelivered` 和 `h_carrying` 两个抽象特征（`atDepot`/`atCustomer` 和 `fuelOK`/`fuelLow` 均被抽象掉，因为只有 `allDelivered` 结合 `atDepot` 才构成目标）。

**抽象状态转移图**：

```
vStart ──(virtual_source)──→ [¬allDelivered, ¬h_carrying] ──loadPkg──→ [¬allDelivered, h_carrying]
                                                                              │
                                                                     moveToCustomer
                                                                              │
                                                                              ↓
                                                                    [¬allDelivered, h_carrying] ──unloadPkg──→ [¬allDelivered, ¬h_carrying]  (还有包裹)
                                                                                                     └──unloadPkg──→ [allDelivered, ¬h_carrying] = vGoal
```

`unloadPkg` 的非确定性体现在：卸下一个包裹后，可能还有包裹未送达（`¬allDelivered`）或全部完成（`allDelivered`）。

## 5. 四域共性总结

| 特征 | TreeChop | NestedVar | Snow | DeliveryFuel |
|------|----------|-----------|------|--------------|
| **论域类型** | 顺序消耗资源 | 嵌套递减 | 位置切换+消耗 | 燃料约束运输 |
| **对象类型** | BranchType | ItemType | LocationType | PackageType |
| **关键导出谓词** | allBranchesChopped, H | h_x1empty, h_hasX2 | allDryCleared, allWetCleared, allCleared | allDelivered, h_carrying |
| **非确定来源** | dropBranch 后可能完成 | decX1 后 X1 可能变空 | 铲雪动作可能成功/失败 | unloadPkg 后可能全部完成 |
| **初始公式** | arm_empty ∧ ¬treeDown ∧ ∀b(onTree(b)∨b=Trunk) | x2empty ∧ ∃i inX1(i) | atDry ∧ ∃l drySnow(l) | atDepot ∧ fuelOK ∧ ¬fuelLow ∧ ∃p atDepotPkg(p) |
| **目标公式** | treeDown | h_x1empty ∧ x2empty | atDry ∧ allCleared | atDepot ∧ allDelivered |
| **实例数** | 2 | 1 | 1 | 3 |

### 抽象机制的通用模式

每个论域遵循相同的 **两层架构**：

1. **低层（Low-Level / domain/）**：完整的参数化 PDDL，包含对象类型、带参动作、一阶导出谓词。这一层可直接用经典规划器或用于模拟执行。

2. **高层 FOND 抽象（autogenerated/）**：通过**量化消除**（quantifier elimination）将所有对象移除，仅保留导出谓词的布尔组合作为抽象状态特征。动作被投影为抽象特征上的非确定性转移——这正是 FOND (Fully Observable Non-Deterministic) 规划的形式化需求。`virtual_source_act` 作为初始抽象状态的来源，其非确定性分支对应不同对象数量实例的初始抽象。
